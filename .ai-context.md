# ResidManager - Contexte Technique & Architecture Projet

## 1. Stack Technique

- **Langage :** Kotlin 2.x
- **Plateforme :** Kotlin Multiplatform (KMP)
- **UI Client :** Jetpack Compose Multiplatform (Desktop JVM, Android, iOS, Web JS / Wasm)
- **Navigation Client :** Jetpack Navigation 3 (`androidx.navigation3.runtime.NavKey`, `NavBackStack`, `NavDisplay`)
- **Injection de Dépendances :** Koin (`org.koin:koin-core`, `koin-compose`)
- **Langage & Conventions :**
  - **Anglais strict** pour tout le code (noms de fichiers, classes, fonctions, variables, constantes, commentaires, KDoc, logs).
- **Architecture Client :** Clean Architecture + MVI (`MviViewModel<State, Intent, Effect>`) + UseCases + Repositories
- **Conventions UI & Écrans :**
  - Navigation 3 systématique (`NavKey`, `NavBackStack`, `NavDisplay`) au lieu de navigation par variables.
  - Séparation stricte : un écran par fichier.
  - Découpage en composants réutilisables (`ui/components/`, limite <= 250 lignes/fichier).
  - Icônes Material Design uniquement (aucun emoji pour les icônes).
- **Design System :** "Emerald Estate" Dark Mode (`DESIGN.md`, `ResidTheme`)
- **Backend :** Ktor 3 (Server JVM, Netty)
- **Base de données :** PostgreSQL avec JetBrains Exposed (DAO / DSL)
- **Sérialisation :** KotlinX Serialization (JSON)
- **Gestion des dépendances :** Gradle Version Catalog (`gradle/libs.versions.toml`)

---

## 2. Structure Réelle des Modules

```text
:core                  -> Modèles et utilitaires multiplateformes communs agnostiques
:app:shared            -> Code UI Compose partagé, ViewModels MVI, UseCases, Repositories, Client HTTP Ktor
:app:androidApp        -> Application native Android
:app:webApp            -> Application Web (Kotlin/Wasm & JS)
:app:iosApp            -> Application native iOS
:server                -> Serveur API REST Ktor autonome (Routing, Services, Schéma Exposed PostgreSQL)
```

## 3. Dossier de Règles Spécialisées (`.ai/`)

Pour les détails d'implémentation, se référer aux sous-dossiers :
- `.ai/architecture.md` : Découpage des responsabilités et isolation multi-modules.
- `.ai/compose-ui.md` : Guide de style Compose, tokens de design, structure MVI détaillée.
- `.ai/backend-ktor.md` : Architecture en 3 couches du serveur Ktor et gestion des transactions DB.
- `.ai/domain-rules.md` : Règles d'invariants métier (Baux, Électricité, Tickets, Devises).

## 4. Commandes Gradle Clés

- **Lancer le serveur backend en local :**
  ```bash
  ./gradlew :server:run
  ```
- **Lancer le serveur backend en local pour utiliser les schémas de base de données de développement:**
  ```bash
  ./gradlew :server:runDevelop
  ```
- **Lancer le serveur backend en local pour utiliser les schémas de base de données de production:**
  ```bash
  ./gradlew :server:runMain
  ```
- **Lancer les tests du backend :**
  ```bash
  ./gradlew :server:test
  ```
- **Compiler le module partagé client :**
  ```bash
  ./gradlew :app:shared:assemble
  ```
- **Compiler l'application web :**
  ```bash
  ./gradlew :app:webApp:jsBrowserDevelopmentRun --continuous
  ```
- **Lancer les tests du code partagé :**
  ```bash
  ./gradlew :app:shared:allTests
  ```
- **Compiler l'application Android :**
  ```bash
  ./gradlew :app:androidApp:assembleDebug
  ```
